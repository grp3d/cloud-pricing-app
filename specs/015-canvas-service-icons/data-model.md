# Data Model: Canvas Service Icons & Per-Architecture Pricing Results

This feature adds **no Postgres tables or columns**. It adds one field to an API response,
resolved read-only from Parquet, and a set of frontend-only values, one of which is persisted in
browser `localStorage`.

---

## 1. `SKUSelectionOut.product_family` (API response field, backend → frontend)

| Field | Type | Source | Notes |
|---|---|---|---|
| `product_family` | `string \| null` | `product_dim.product_family` for `(service_code, sku)` in the owning Collection's region (for a Connector-owned selection, its "from" Collection's region) | Resolved at response time in the same batched lookup as `attributes`. Never stored. `""` in the data is normalized to `null`. `null` also when the SKU has no matching row. |

This follows the same resolution and region-scoping rules as the existing `attributes`
(`fromRegionCode` for AWSDataTransfer). See [contracts/api.md](contracts/api.md).

## 2. Service Icon Mapping (frontend, static, generated)

`frontend/src/lib/awsServiceIcons.generated.ts`, generated by
`backend/scripts/generate_aws_service_icon_map.py` and checked in.

| Name | Shape | Meaning |
|---|---|---|
| `AWS_SERVICE_ICON_BY_CODE` | `Record<string, string>` | service code → icon file stem (e.g. `"AmazonDynamoDB" → "Amazon-DynamoDB"`) |
| `AWS_SERVICE_ICON_BY_CODE_AND_FAMILY` | `Record<string, Record<string, string>>` | service code → product family → icon file stem (e.g. `AmazonEC2 → { "NAT Gateway": "Amazon-Virtual-Private-Cloud" }`) |
| `AWS_FALLBACK_ICON` | `{ light: string; dark: string }` | AWS Cloud group icon stems |
| `AWS_DATA_TRANSFER_ICON` | `{ light: string; dark: string }` | General "Data Stream" resource icon stems |

**Resolution rules** (`resolveAwsServiceIcon(serviceCode, productFamily)`), applied in order:
1. `BY_CODE_AND_FAMILY[serviceCode]?.[productFamily]` when `productFamily` is non-null.
2. `serviceCode === "AWSDataTransfer"` → the data-transfer icon.
3. `BY_CODE[serviceCode]`.
4. Otherwise the fallback icon.

The result is `{ lightUrl, darkUrl, isFallback }`. For ordinary service icons,
`lightUrl === darkUrl`. The function is deterministic: the same inputs always give the same
output (FR-003). Every stem in the map MUST have a matching file in
`frontend/src/assets/aws-icons/`, and a unit test enforces this.

## 3. Service Pop-up Content (frontend, derived, not stored)

`buildServicePopupLines(selection): string[]` in `frontend/src/lib/servicePopup.ts`.

| # | Line | Present when |
|---|---|---|
| 1 | `<service_code>` | always |
| 2 | `Sku: <sku>` | always (the real SKU, including for data transfer) |
| 3 | `<region-pair label>` | `awsDataTransferLabel(service_code, attributes)` is non-null |
| 4 | `<identifying-detail summary>` | `summarizeAttributes(attributes)` is non-empty |
| 5 | `UsageType: <attributes.usagetype>` | value non-empty |
| 6 | `Operation: <attributes.operation>` | value non-empty |

Accessible name = `lines.join(", ")`.

## 4. Priced Contents Entry (frontend, value type)

This extends the existing `PriceChangeSelection` (`lib/priceChange.ts`) with the region.

| Field | Type | Notes |
|---|---|---|
| `service_code` | string | |
| `sku` | string | |
| `pricing_term` | PricingTerm | |
| `purchase_option` | PurchaseOption | |
| `usage_quantity` | string | |
| `region` | string \| null | owning Collection's region (for a Connector-owned selection, its "from" Collection's region) |

**Equality**: `pricedContentsEqual(a, b)` is an order-independent multiset comparison over all
six fields. It has no ids, so moving a service between two same-region Collections is not a
change.

## 5. Architecture Pricing Result Entry (frontend, persisted per browser)

`localStorage` key: `cloud-pricing-result-<architectureId>`. Read and written by
`lib/architecturePricingResults.ts` with try/catch and a type guard. A missing, corrupt or
wrong-shape value reads as `null`.

| Field | Type | Notes |
|---|---|---|
| `version` | `1` | Shape version. Any other value reads as `null`. |
| `result` | `CalculationResult` (the generated API type returned by `api.calculate`) | total, currency, line_items, warnings, unpriceable, snapshot_date, as returned |
| `duration` | `CalculationDuration` | Duration the result was computed at (FR-015, FR-018b) |
| `priceChange` | `string \| null` | Price Change displayed with this result (FR-022) |
| `pricedContents` | `PricedContentsEntry[]` | Contents at request time, used for staleness (FR-018a) |
| `calculatedAt` | ISO-8601 string | Informational only, not displayed in v1 |

**Not persisted**: per-architecture calculation **error** messages, held in an in-memory
`Map<architectureId, string>` (FR-021), and the in-flight request set.

**Relationship to the existing Prior Calculation** (`cloud-pricing-prior-calculation-<id>`): these
are separate keys with separate purposes. The Prior Calculation is the price-change *baseline* and
keeps its current semantics. The Result Entry is *what the pricing column displays*. Both are
written together on a successful calculation.

### Lifecycle and state transitions (per architecture)

```text
             switch-in, has services,          success
  (none) ───────────────────────────────▶ calculating ─────────▶ stored (fresh)
     ▲          no stored entry                │  failure             │
     │                                         ▼                      │ priced contents
     │                                  error (in memory) ◀─┐         ▼ diverge
     │                                         │ retry/     │   stored (out of date)
     │                                         └─Calculate──┘         │ contents match again
     │                                                                ▼
     │                                                         stored (fresh)
     │  architecture deleted: entry removed
     └──────────────────────────────────────── any state

  Calculate (manual) from any stored state → calculating → stored (fresh), replacing the entry
```

- **Validation rules**:
  - An entry is only ever written under the `architectureId` captured when the request was made
    (FR-020).
  - Auto-calculation fires only when the architecture has ≥1 SKU selection, has no entry, and has
    no in-flight request (FR-017).
  - The displayed entry is always `entries[activeArchitectureId]` (FR-016).
