# Data Model: Deferred UI and Admin Fixes

No new tables and no migration.

## 1. Preferences: `appearance` section (new, optional)

Part of the existing per-user preferences document (019, `Preferences` in
`backend/src/models/schemas.py`).

| Field | Type | Rules |
|---|---|---|
| `appearance.theme` | `"light"` \| `"dark"` | Optional; absent means light (FR-006). Strict: no other keys. |

- Saved only for a logged-in user (a user with a username). A patch containing `appearance`
  from a guest is refused (403), and the client never sends one (FR-005).
- Sending `appearance: null` clears it back to light, like the other sections.
- `schema_version` unchanged: the section is optional and additive.

## 2. Browser storage

| Key | Holds | Written | Removed |
|---|---|---|---|
| `cloud-pricing-guest-id` (existing) | the browser's guest UUID | once, on first use | never |
| `cloud-pricing-current-identity-id` (existing) | the UUID sent as the bearer token | on login; on Log out set to the guest ID | never |
| `cloud-pricing-theme` (new) | `{ "user_id": "<uuid>", "theme": "dark" }` | when a logged-in user's theme is applied | on Log out, or whenever the current identity is a guest |

The theme cache is applied before first paint only when its `user_id` equals the current
identity (research R3).

## 3. `HistoryOut` (existing, now nullable per provider)

`providers.<p>.history: HistoryOut | null`; `null` when the provider's history state can't be
read (FR-013). Fields unchanged: `weeks_built`, `weeks_total`, `gaps`, `backfill`
(`pending` | `running` | `done` | `failed`), `last_error`, `last_built_at`.

Shown state, in order of precedence:

| Condition | Shown |
|---|---|
| `history` is null | Unavailable |
| `backfill == "running"` | Building (N of M weeks) |
| `backfill == "failed"` | Failed: `last_error` |
| `weeks_total == 0` | No history yet |
| `gaps` non-empty | N weeks missing (plus weeks built and last built) |
| otherwise | Complete: N weeks, last built `last_built_at` |

## 4. `IssueOut` (existing, extended)

| Field | Change |
|---|---|
| `provider` | new: `"aws"` \| `"gcp"` \| `"azure"` |
| `kind` | adds `"marketplace_without_icons"` |
| `count` | new, optional: the number of Marketplace and third-party services with no icon (only on `marketplace_without_icons`) |

`missing_icon` issues keep `service_code`, `service_name`, `is_new` and `message`; the message
names the provider's fallback ("…shows the generic GCP tile on the canvas").

## 5. Icon maps for the backend (new generated files)

`backend/src/pricing_data/gcp_service_icons.json` and `azure_service_icons.json`:

```json
{ "by_id": { "<service id>": "<icon stem>" },
  "overrides": { "<service id>": [ { "match": "<family pattern>", "icon": "<stem>" } ] } }
```

Generated by `generate_provider_service_icon_map.py` from the same mapping as
`frontend/src/lib/{gcp,azure}ServiceIcons.generated.ts`; never hand-edited. A service has an
icon when its ID is in `by_id`.
